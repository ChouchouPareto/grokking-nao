# 第 2 阶段技术开发文档｜切片 2：AI 建议引擎

> 配套文档：`Grokking恼_PRD_v1.0_第一版.md`、`AI产品Vibe Coding通用技术栈手册.md`、`技术适配声明.md`、`前端技术适配声明.md`
> 本文档只覆盖第 2 阶段（切片 2）。AI 开发时不得提前实现语义场景、首页管理等后续能力。

---

## 一、阶段目标

- **用户任务（一句话）**：AI 先理解用户在想什么，再通过主动展开或新增关键词后的关系扫描，帮助用户发现此前没想到的视角与连接。
- **交付范围（对齐 PRD 8.1 P0、第 10/20 节）**：
  1. 后端 AI 代理（FastAPI），安全持有模型 Key，调用大模型生成 ≤3 条建议；
  2. 建议类型：`node`（缺失节点）、`edge`（潜在连接）、`question`（启发式追问），每条含简短理由；
  3. 前端"帮我展开"按钮启用，请求中展示非阻塞加载态；
  4. 新节点/连接以**半透明候选态**出现在空间，不进入正式网络；
  5. 用户对每条建议可「接受 / 编辑后接受 / 拒绝」；接受后候选内容转为正式状态并本地保存；
  6. 被拒绝的相同建议不在紧接着的下一轮原样重复；
  7. AI 请求状态：`idle → loading → success / partial / error / cancelled`，失败时保留手动思考能力并提供重试。
  8. 每次建议返回意图画像：主要意图、思考阶段、已有维度、缺失维度与置信度；建议维度由画像动态决定。
  9. 用户双击画布空白处可在对应空间位置新增节点；默认 3 秒防抖后扫描该节点与现有节点的潜在连接。
- **阶段产物**：FastAPI 后端 + 前端候选态交互（正式产品切片）。
- **验收标准**：见第十一节。
- **明确不做**：语义场景氛围、首页管理/JSON 导入导出、撤销重做、图片导出、流式 SSE、移动端复杂编辑。
- **本阶段打通的主链路片段**：`输入/新增关键词 → 意图识别 → 动态维度展开或定向关系扫描 → 半透明候选态 → 人工确认 → 正式网络 + 本地保存`。

## 二、技术适配摘要

- 引用《技术适配声明》结论：开发路径 = 纵向切片；数据**本地优先**；后端为**无状态 AI 代理**。
- 本阶段采用：FastAPI + Pydantic + pytest（后端）、模型走 OpenAI 兼容接口（DeepSeek，可换）。
- 本阶段启用按需模块：httpx（调用 LLM）、python-dotenv（本地 Key）；前端复用现有 store / 画布。
- 本阶段偏离/暂缓：暂缓 SSE（AI 建议为短请求）、暂缓关系型数据库（数据仍本地 IndexedDB）。
- 开发路径：纵向切片。

## 三、技术栈与模型

- 后端：Python 3.12 + FastAPI + Uvicorn + Pydantic v2 + httpx + python-dotenv + pytest。
- 模型：**DeepSeek（`deepseek-chat`）**，OpenAI 兼容接口 `https://api.deepseek.com/chat/completions`。可配置供应商（base_url / model / api_key）。
- **无 Key 不阻塞**：后端检测无 Key 时进入 **mock 模式**，返回确定性示例建议，保证全链路可开发、可验收；真实模型冒烟在提供 Key 后补做。
- 前端：沿用切片 1（Next.js + R3F + zustand + idb）。

## 四、环境与配置

- 后端 `.env`（不提交）：`LLM_API_KEY`、`LLM_BASE_URL`（默认 DeepSeek）、`LLM_MODEL`（默认 `deepseek-chat`）。提交 `.env.example`。
- 前端公开配置：`NEXT_PUBLIC_API_BASE_URL`（默认 `http://localhost:8010`），不含密钥。
- 端口：后端 **8010**（8000 被占用）、前端 3010。开发期后端开 CORS 允许 localhost:3010；生产改 `rewrites` 同源代理。
- 依赖：后端用 Python 3.12 venv。

## 六、数据、资产与状态

### 后端无持久化
后端是无状态 AI 代理，不存业务数据；Idea/节点/连接仍在前端 IndexedDB。后端仅在内存中处理单次请求。

### AI 建议（前端 AISuggestion，PRD 19.4）

```ts
interface AISuggestion {
  id: string;              // 后端生成
  requestId: string;       // 本轮请求标识
  type: "node" | "edge" | "question";
  content: string;         // 建议文本
  reason: string;          // 简短理由
  relatedNodeIds: string[];
  sourceNodeId?: string;   // edge 类型
  targetNodeId?: string;
  edgeNote?: string;
  dimension: string;       // 本条建议补充的思考维度
  relation?: string;       // edge 的关系类型
  strength?: number;       // edge 关系强度 0..1
  status: "pending" | "accepted" | "edited_accepted" | "rejected";
}
```

### 状态流

- 建议：`pending → accepted | edited_accepted | rejected`。
- 节点：`candidate → formal`（接受后）或 `candidate → rejected`；正式节点不由 AI 降级。
- AI 请求：`idle → loading → success | partial | error | cancelled`（PRD 18.3）。
  - `loading`：非阻塞，用户可继续操作空间；
  - `partial`：展示已成功解析的建议并说明不完整；
  - `error`：保留手动思考，提供重试，不写入残缺内容；
  - `cancelled`：离开 Idea 或取消后停止展示本轮结果。

## 七、API / 工具设计

`POST /api/v1/ai/suggestions`

请求体：
```json
{
  "idea_id": "uuid",
  "seed_text": "原始念头",
  "title": "标题",
  "nodes": [{"id": "n1", "text": "生鲜"}],
  "edges": [{"source_node_id": "n1", "target_node_id": "n2", "note": "可选"}],
  "rejected_summary": ["已拒绝建议摘要"],
  "focused_node_id": "n1",
  "mode": "deep_expand",
  "trigger_node_ids": []
}
```

响应体（成功）：
```json
{
  "request_id": "uuid",
  "intent_profile": {
    "primary_intent": "验证一个生鲜订阅服务",
    "thinking_stage": "探索",
    "dimensions_present": ["核心概念"],
    "dimensions_missing": ["使用情境", "约束与风险", "反例"],
    "confidence": 0.82
  },
  "suggestions": [
    {"id": "s1", "type": "node", "content": "下班后无人收货", "reason": "补足真实使用情境", "dimension": "使用情境", "related_node_ids": ["n2"]},
    {"id": "s2", "type": "edge", "content": "连接「社区团长」与「损耗」", "reason": "团长的集单密度可能改变损耗", "dimension": "跨维联系", "relation": "因果", "strength": 0.78, "related_node_ids": ["n1","n4"], "source_node_id": "n1", "target_node_id": "n4", "edge_note": "集单密度影响履约损耗"},
    {"id": "s3", "type": "question", "content": "在哪种情况下订阅反而比即时购买更麻烦？", "reason": "寻找反例", "dimension": "反例", "related_node_ids": ["n3"]}
  ]
}
```

- 每轮 ≤3 条；`edge` 必须引用已存在的节点 id，否则后端丢弃或改判为无效。
- 错误响应统一 `{"error": {"code": "...", "message": "..."}}`，不泄露堆栈。
- 健康检查：`GET /api/v1/health` → `{"status": "ok", "mock": true|false}`。

## 八、Prompt 设计

- 角色：AI 是"陪伴思考者"，不是结论生成器。
- 输入变量：`seed_text`、`title`、节点文本列表、连接列表、已拒绝摘要、聚焦节点、请求模式、触发节点。
- 输出格式：JSON 对象 `{intent_profile, suggestions}`；解析器仍兼容旧版纯数组响应。
- 格式约束三件套（手册 9.3）：
  1. **正反例**：明确"只输出 JSON，禁止 Markdown 代码块/解释文字；type 只能取 node/edge/question"。
  2. **解析器宽容**：剥除 ```json 围栏、截取首个 `[` 到末 `]`，再 `json.loads`，失败走有限重试。
  3. **数量约束不遵守 ≠ 解析错误**：超过 3 条时截取前 3 条并计为质量瑕疵，不反复重试烧钱。
- 建议策略：先判断探索/定义/验证/决策等阶段，再从该意图真正缺失的维度取至少两个不同方向；禁止机械固定为成本和目标客户。
- `relation_probe` 只返回连接建议，且至少一端必须属于 `trigger_node_ids`，防止脱离新节点重讲整张图。

## 九、验收界面 / 纵向切片

- 前端"帮我展开"按钮启用，显示 AI 请求状态。
- 建议渲染：`node`/`edge` 以半透明候选态进画布；`question` 在建议面板展示。
- 候选内容可接受/编辑后接受/拒绝；拒绝后不立即重复。
- 双击空白处新增节点；自动关系扫描使用 3 秒防抖、同图缓存与工具栏开关，避免频繁调用和打断。

## 十、测试要求

- 第一层（mock 自动化）：后端 pytest 覆盖新旧响应解析、意图变化、动态维度、schema 校验、edge 引用与触发节点约束、mock 模式返回结构。
- 第二层（真实冒烟）：**待真实 Key**。无 Key 时如实标注"待验"，不得用 mock 冒充。
- 前端：扩展 e2e——点击"帮我展开"→ 出现候选态 → 接受 → 进正式网络；沿用 lint/typecheck/build 门槛。

## 十一、验收清单（产品经理照做）

1. 进入一个已有 ≥3 个节点的 Idea，看到"帮我展开"可点击。
2. 点击后出现非阻塞加载提示，几秒内返回 ≤3 条建议。
3. 新关键词建议以半透明节点出现在空间，与正式节点有明显视觉差异。
4. 潜在连接建议以半透明连接出现。
5. 启发式问题在面板中展示，不进入网络。
6. 接受一条节点建议 → 转为正式节点并显示"已保存"；刷新后仍在。
7. 编辑后接受一条建议 → 以编辑后的文本进入正式网络。
8. 拒绝一条建议 → 从空间消失；紧接着再点"帮我展开"不原样重复该建议。
9. 断开后端（或后端不可用）→ 手动添加/连接/保存仍可用，失败有可理解的提示与重试。
10. 无 Key（mock 模式）→ 功能可跑通，界面标注 mock。
11. 双击画布空白处输入一个新关键词 → 节点落在对应区域，约 3 秒后出现只与该批新节点有关的候选连接。
12. 关闭「自动找联系」→ 后续新增节点不自动发起关系扫描。

## 十二、风险与待确认项

- 真实 Key 未提供：真实模型冒烟"待验"，已用 mock 推进开发与前端联调。
- 建议质量依赖 prompt 与图结构：首版策略（PRD 20.3）为默认，不额外调优。
