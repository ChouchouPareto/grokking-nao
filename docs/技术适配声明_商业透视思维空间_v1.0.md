## 1. 产品形态判断

- 产品类型与核心任务：AI辅助的空间思考Web产品。用户输入主题与探索方向，AI生成横向业态、纵向产业链和少量洞察；用户在3D画布确认连接、创建思考分支和节点记录，并可主动调用基于位置的环境启发建议。
- 核心交互：分阶段确认 + 可视化编辑 + 动态模型调用。AI候选不能自动写入正式图谱，方向、节点、连线、分支合并和AI记录均需要用户确认。
- 开发路径：采用纵向切片。画布、候选确认、方向入口和环境建议本身决定Agent是否可用，不能只做后端JSON后再补界面。
- 当前阶段范围：完成“主题/模式/方向 → 商业透视候选 → 用户确认 → 节点分支/记录 → 可选位置授权与环境建议”的单用户Web闭环；保留原有日常发散、项目存档、邀请码登录和内容安全。

## 2. 采用的默认方案

- FastAPI + Pydantic：延续现有后端，负责AI契约、输入输出校验、安全拦截和统一错误。
- pytest：延续现有后端测试，新增方向、商业透视、环境建议和安全边界用例。
- Next.js App Router + TypeScript + Tailwind CSS：延续现有Web终端，不建立平行验收页。
- Zustand：继续管理当前画布交互状态；业务数据仍通过持久化层保存，避免只留内存。
- IndexedDB：当前为邀请码单用户体验阶段，继续采用已有`idb`持久化，并通过`schemaVersion`迁移旧项目。
- `/api/v1`：沿用已有AI API前缀，新接口使用同一版本，不破坏现有调用。
- DeepSeek兼容接口：沿用后端配置化模型服务；模型名、base_url、Key和超时继续由环境变量控制。
- Git：每个切片独立提交；技术方案先提交并打标签，开发版本可回退。

## 3. 触发的按需模块

- 浏览器Geolocation：由“主动授权当前位置”触发；只在用户点击后调用。
- 地图适配器：由“附近现实环境启发”触发；用统一接口隔离高德或其他供应商。
- 高德Web服务：当前只预留适配器和环境变量；配置Key后启用地理编码与附近环境POI。没有Key时使用手动位置标签和通用环境建议，不伪造地点。
- 结构化AI契约：新增方向建议、商业透视和环境建议三类Pydantic结构；这是模型输出校验的强制实现，不是可选美化。
- 轻量跨会话偏好：只在项目内保存方向、环境偏好、拒绝历史与建议反馈；暂不建立全局用户画像数据库。
- 语义布局：在现有Three.js/React Three Fiber与d3-force-3d上增加布局约束，不引入第二套图引擎。

## 4. 偏离或暂缓的默认方案

- Python 3.11默认值：继续使用项目已验证的Python 3.12.13；避免无收益的降级迁移，现有FastAPI与测试已通过。
- npm默认值：继续使用项目现有pnpm 11与`pnpm-lock.yaml`；不得混用npm/yarn。
- 关系型数据库：暂缓。当前项目数据只在单浏览器本地使用，先升级IndexedDB schema；当正式账户、多设备同步、一次性邀请码、付费权益或并发修改启动时，必须迁移到服务端数据库并提供迁移与回滚方案。
- SSE：暂缓。当前三类模型调用目标是短结构化响应，使用普通POST并设置超时；当真实冒烟出现明显长等待或需要逐步展示时再引入SSE。
- 工作流运行时、任务队列、子Agent：暂缓。当前闭环可用确定性状态机和三类有限AI调用完成，引入复杂编排只会增加恢复成本。
- 实时天气与音乐账户：暂缓到下一阶段。MVP环境建议不读取Spotify/Apple Music账户，也不自动播放。
- 真实附近POI：代码支持但上线启用取决于地图Key、配额和隐私提示；无Key时必须明确降级。

## 5. 强制底线检查

- 密钥与隐私：通过设计。模型Key和地图服务Key只在服务端/部署Secret；浏览器公开Web Key如供应商要求使用，必须配套域名白名单和安全密钥代理。定位只主动请求，不持续追踪。
- 数据与任务可恢复：当前需处理。将Idea schema从v3升级到v4，方向、分支、节点记录、位置上下文和环境反馈必须随项目持久化；旧项目打开时确定性迁移。
- 输入输出校验：当前需处理。新增API全部用Pydantic校验；模型JSON经过宽容解析、数量截断、枚举/引用/安全校验和一次格式修复。
- 错误与日志边界：通过现状并扩展。统一返回用户可理解错误，不泄露堆栈；日志记录模型、耗时、错误类型和数量，不记录Key、精确坐标和完整用户原文。
- 测试与真实模型验收：mock测试每次切片必跑；开发完成后分别用“川菜商业深思”“方向建议”“环境建议”完成真实模型冒烟。地图无Key时只能验收授权/降级链路，不能声称真实POI已通过。

## 6. 需要产品经理决定的问题

- 无阻塞开发问题。默认先实现可替换地图适配器与无Key降级；未来提供高德Web服务Key后启用真实附近环境。
- 首批用户画像仍待内测验证，但不阻塞以“观察本地生意、选品或开店的个人”为当前文案假设；该假设保持可配置，不写死业务逻辑。
