# 分支规划

> 项目：Grokking恼
> 主分支：`main`（稳定集成基线）
> 说明：每个切片在独立分支开发，验收通过后合并回 `main`。

## 当前分支

| 分支 | 内容 | 状态 |
|---|---|---|
| `main` | 稳定基线（当前 = 切片 1 完成） | 活跃 |
| `slice/2-ai` | 切片 2：AI 建议引擎（帮我展开 → 候选态 → 接受/编辑/拒绝，引入 FastAPI 代理） | 待开发 |
| `slice/3-scene` | 切片 3：语义场景（6–8 套氛围 + 自动选择 + 锁定/手动切换） | 待开发 |
| `slice/4-manage` | 切片 4：首页管理（重命名/复制/删除）+ JSON 导入导出 + 首次引导 | 待开发 |

## 标签

- `slice-1-core`：切片 1 完成基线（核心思考闭环）

## 工作流

```text
开始切片 N：
  git checkout slice/N-xxx
  （开发 + 验证）

切片 N 验收通过后：
  git checkout main
  git merge --no-ff slice/N-xxx
  git tag slice-N-xxx
  git push（如配置了远程）

下一个切片从「更新后的 main」再开分支（若旧分支已过时，可 reset 到新 main 重建）。
```

> 注意：预设的 `slice/3-scene`、`slice/4-manage` 目前都指向切片 1 基线；开发到对应阶段时，若 main 已前进，应先 `git checkout slice/N && git reset --hard main` 再开工，或直接从最新 main 新建分支。
