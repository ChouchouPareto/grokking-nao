## 1. 项目判断

- **产品类型**：3D 空间思考工具（以 3D 关键词网络为核心的思考工具；AI 是陪伴建议者，不是内容生成器）。
- **主要用户**：脑中已有念头、尚未形成清晰结构的个人思考者（产品经理、创业者、设计师、创作者、研究型工作者）。
- **主要终端**：桌面 Web（Chrome / Edge / Safari）。移动端第一版只保证「能打开、能浏览」，复杂编辑不作为 P0 门槛（对齐 PRD 22.3）。
- **新项目或已有项目**：新项目；切片 1（核心思考闭环）已实现并验证。
- **本阶段业务目标**：切片 1——从"我有一个念头"走到"标记一条新发现"，本地保存并可恢复；前端即产品本体，不是展示壳。

## 3. 技术选择

- **框架与版本**：Next.js 16.3.2（App Router）+ React 19 + TypeScript strict + Tailwind CSS 4。运行环境 Node 24（当前活跃 LTS，手册参考基线 22，已锁定依赖文件）。
- **样式与组件策略**：Tailwind CSS + CSS 语义变量（`--bg/--surface/--line/--ink/--primary/--discovery` 等）；组件先用原生 HTML + 轻量自建（`ui.tsx`：Button/TextInput/Modal）。**暂缓** Radix UI / shadcn（对话框、菜单数量尚少）。
- **数据请求与状态策略**：**本地优先**——IndexedDB（`idb` 封装）持久化；全局客户端状态用 **zustand**（节点/连接/选择/聚焦/模式/保存状态跨画布与面板共享，符合手册 C 层触发条件）；切片 1 无 HTTP 请求。
- **流式通信策略**：暂无。切片 2 AI 建议为短请求（每轮 ≤3 条），**暂缓 SSE**；若后续"帮我展开"变长再评估。
- **表单方案**：原生受控组件（标题、关键词、连接说明均为轻量输入）。**暂缓** React Hook Form + Zod（无复杂/多步表单）。
- **测试方案**：Playwright-core 真实浏览器 E2E（复用本机 Chrome，覆盖"创建→加节点→连接→标记新发现→保存→刷新恢复→聚焦"）+ `lint / typecheck / build` 交付门槛。**暂缓** Vitest / React Testing Library（切片 1 以真实浏览器闭环为准）。
- **部署环境**：本地开发（端口 3010，3000 已被占用）；生产部署（standalone 输出、`rewrites` 同源代理、HTTPS）待《上线部署手册》执行。

## 4. Agent 状态

- **后端状态 → 前端统一状态映射**：切片 1 无后端任务状态；本地保存状态 `saving → saved | failed`（对齐 PRD 18.4）。切片 2 引入 AI 请求状态 `idle → loading → success / partial / error / cancelled`（PRD 18.3），AI 候选态映射为节点的 `status: "candidate"`（半透明）。
- **等待用户确认方式**：AI 建议以**半透明候选态直接出现在空间**，用户就地处"接受 / 编辑后接受 / 拒绝"（非阻塞弹窗）；未经接受不得进正式网络。
- **取消、重试、断线恢复方式**：本地自动保存（无强制保存按钮）；刷新后按 URL 的 Idea id 从 IndexedDB 恢复节点/连接/位置/新发现状态。AI 短请求失败走统一错误 + 重试，不影响手动思考。
- **任务 ID 和恢复入口**：`/idea/[id]` 即恢复入口（路由参数 = Idea id）；无长任务、无服务端任务中心。

## 5. 页面与产物

- **核心页面**：首页 `/`（主输入框 + 本地 Idea 列表）；思考空间 `/idea/[id]`（3D 画布 + 顶栏 + 底部工具栏 + 选中后的节点/连接面板）。
- **核心业务闭环**：输入念头 → 创建 Idea → 添加关键词 → 3D 自动布局 → 手动连接 → 标记"这是新发现" → 本地保存 → 刷新恢复 → 继续探索。
- **产物类型和预览方式**：无多媒体产物（思考网络本身即产物）；3D 画布用 WebGL（three.js），节点标签用 DOM（drei `Html`）保证中文可读。
- **响应式目标**：桌面 1280 / 1440 为主要验收宽度；移动端 390 保证可打开、节点可浏览，复杂编辑不进 P0。

## 6. 偏离本手册的地方

| 偏离项 | 原因 | 影响 |
| --- | --- | --- |
| 引入 3D 渲染栈（three + React Three Fiber + d3-force-3d） | 手册默认栈不含 3D；产品首期核心即"3D 关键词渲染"，属手册 2.2 明确的"可参考不能照搬"场景 | 依赖体积增大；已用真实浏览器 E2E 验证可运行 |
| 前端即产品本体（纵向切片，非后端先行） | 3D 画布、手动连接、候选态确认等交互本身决定产品可用性 | 第一阶段即有真实可操作界面 |
| 本地优先（IndexedDB），无服务端数据 | PRD 明确"本地保存、无账号、无云同步" | 数据不跨设备、清浏览器即丢（靠后续 JSON 导出兜底） |
| 节点标签用 DOM（drei `Html`）而非 WebGL 文本 | 中文字形与可读性优先，避免 CJK 字体加载 | 60 节点基线若帧率跌破 30 FPS，按 PRD 14.1 降级或迁移 troika 文本 |
| 测试以真实浏览器 E2E 替代 Vitest/RTL 单测 | 切片 1 核心价值在 3D 交互与本地持久化，单测覆盖意义弱 | 后续切片补充纯函数单测（解析器/状态机） |

以上均不触犯 A 层强制底线（TypeScript strict、接口集中、密钥不进前端、加载/空/失败状态、真实浏览器验收）。
