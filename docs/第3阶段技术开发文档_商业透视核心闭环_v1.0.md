# 第3阶段技术开发文档｜商业透视核心闭环 v1.0

> 文档版本：1.0.0  
> 配套文档：`商业透视思维空间_开发方案_v0.1.md`、`技术适配声明_商业透视思维空间_v1.0.md`、《AI Agent 产品 Vibe Coding 通用技术栈手册 V2.1》。  
> 本文档覆盖商业透视第一条完整纵向切片，不提前实现支付、正式账户、多端同步和团队协作。

## 一、阶段目标

### 交付范围

1. 首页以搜索输入为主入口，支持`商业深思`与`日常发散`。
2. 发散前可填写探索方向，或请求2–3个AI方向候选并确认。
3. 商业深思生成5个横向方向、5–10个纵向链路节点和1–2条洞察。
4. 画布能够区分横向、纵向、AI候选、用户确认和洞察关系。
5. 任意正式节点可创建思考分支并追加思考记录。
6. 用户可主动授权位置并请求环境启发；无地图Key或拒绝定位时可完整降级。
7. 旧项目无损迁移，原日常发散与总结继续可用。

### 阶段产物

- 三类版本化AI API及测试；
- Idea schema v4及迁移；
- 首页方向/模式/位置入口；
- 商业语义画布、节点分支与记录界面；
- 环境启发卡和无Key地图适配器；
- README、mock测试、真实模型冒烟记录与桌面/WAP验收结果。

### 验收标准

- 用“四川菜”创建商业深思项目，首轮返回恰当的横向类别、5–10个纵向节点和不超过2条洞察。
- 用户能采纳/编辑AI方向，也能不限定方向继续。
- 用户能从一个正式节点建立分支、保存记录，刷新后数据仍存在。
- AI候选未经点击不得进入正式网络。
- 位置权限只有点击后请求；拒绝定位后仍可获得明确标记的通用环境建议。
- 敏感或提示词注入输入继续被服务端拒绝。
- 桌面与375px宽度下没有主流程遮挡，触控目标不小于44px。

### 明确不做

- 正式注册、付费、额度、一次性邀请码和多设备同步；
- 后台持续定位、轨迹记录、自动读取音乐账户；
- 天气API、路线导航、真实客流或经营收益预测；
- 多人协作、团队分支合并和复杂冲突解决。

### 主链路

`输入主题 → 选择模式 → 填写/确认方向 → 创建项目 → AI商业透视 → 候选态渲染 → 用户接受 → 从节点创建分支/记录 → 主动请求环境建议 → 回来记录新发现`

## 二、技术适配摘要

- 开发路径：纵向切片。
- 本阶段采用：现有Next.js、TypeScript、Tailwind、React Three Fiber、Zustand、IndexedDB、FastAPI、Pydantic、pytest和DeepSeek兼容调用。
- 本阶段启用：schema v4迁移、结构化AI契约、浏览器定位、地图适配器、语义布局约束。
- 本阶段暂缓：数据库、SSE、任务队列、真实天气、音乐账户与复杂Agent编排。

## 三、技术栈与模型

- 前端：Next.js 16.3.2、React 19.2.8、TypeScript 5、Tailwind 4、Zustand 5、idb 8、Three.js/React Three Fiber、d3-force-3d。
- 后端：Python 3.12.13、FastAPI、Pydantic、httpx、pytest。

## 六、数据、资产与状态

### Idea schema v4

- `thinkingMode`: `business | daily`，旧项目默认`daily`。
- `direction`: `{status, text, source, candidates}`。
- `locationContext`: 可选的 `{status, label, city, district, approximateCenter, precision}`；坐标进入持久化前降低精度。
- `branches`: 思考分支数组。
- `nodeNotes`: 节点记录数组。
- `businessInsights`: 商业洞察数组。
- `environmentSuggestions`: 环境建议与用户反馈数组。

### 状态机

方向：`pending → loading → candidates → confirmed`；失败回到`pending`并显示重试。  
AI候选：`loading → candidate → accepted/rejected`；只有accepted写入正式图谱。  
分支：`active ↔ paused → archived`；MVP不允许从archived直接写节点。  
位置：`idle → explaining → requesting → granted/denied/error`；denied/error不阻断主链路。  
环境建议：`idle → loading → ready → accepted/dismissed/completed`。

### 迁移与恢复

- `normalizeIdea`确定性补齐v4字段，不删除旧节点、边、总结与拒绝历史。
- 旧数据读取后写回新schema；写入继续使用IndexedDB事务。
- 删除节点前检查关联分支与记录；当前阶段使用明确确认，后续服务端化时评估软删除。

## 七、API / 工具设计

### `POST /api/v1/ai/directions`

请求：主题、思考模式、可选位置标签。  
响应：2–3个`{text, reason, dimension}`。  
错误：`VALIDATION_ERROR`、`CONTENT_BLOCKED`、`MODEL_UNAVAILABLE`、`MODEL_OUTPUT_INVALID`。

### `POST /api/v1/ai/business-lens`

请求：主题、确认方向、已有节点/边、拒绝历史、可选模糊位置。  
响应：intent、horizontal_clusters、vertical_chain、insights、thinking_stage、environment_cue。  
确定性校验：横向最多5个主要方向；纵向截为5–10个；洞察最多2条；空文本、重复项、非法枚举和危险输出丢弃或整体拒绝。

### `POST /api/v1/ai/environment`

请求：主题、方向、图谱摘要、思考阶段、时间预算、环境偏好、地图供应商返回的环境候选。  
响应：1条主建议、最多1条备选、why_now与return_prompt。  
地图无数据时：`place_name`不得伪造专名，只输出环境类型和“未使用实时附近地点”标记。

### 兼容接口

- 原`/suggestions`用于日常发散及节点关系探测；不删除。
- 原`/summary`继续生成阶段总结；商业模式优先显示新的1–2条洞察。

所有模型调用：单次请求、一次格式修复、有限超时；不允许无限Agent循环。

## 八、Prompt设计

- `DIRECTION_PROMPT_V1`：提供互不重复的探索方向；方向必须是视角而不是直接答案。
- `BUSINESS_LENS_PROMPT_V1`：明确横向相邻业态与纵向产业链差异，使用正反JSON示例；无数据时只表达假设。
- `ENVIRONMENT_PROMPT_V1`：依据思考阶段选择环境行动；必须说明why_now、activity和return_prompt；禁止心理疗效承诺。
- 用户文本放入明确的`UNTRUSTED_USER_DATA`结构，不与系统规则拼成同级指令。
- 输出先宽容解析JSON代码块，再由Pydantic及确定性清洗校验；内容数量偏差用截断处理，不因超量反复烧钱重试。

## 九、验收界面或纵向切片

- 直接扩展现有正式Web产品，不创建临时HTML。
- 首页保持浅色空间视觉；方向候选与AI节点都采用候选态，不与已确认内容混淆。
- 方向输入有可见标签、加载/空/失败状态，不用placeholder代替字段名称。
- 画布侧栏在WAP端使用单侧抽屉/顶部入口，不依赖hover。
- 所有点击目标至少44×44px，键盘有可见焦点；动效遵循`prefers-reduced-motion`。

## 十、测试要求

### 第一层：mock自动化

- 方向建议数量、去重、编辑后确认、失败重试。
- 商业透视横向/纵向数量边界、重复过滤、非法枚举、洞察截断。
- 旧Idea v3迁移v4且节点/边/总结不丢失。
- 分支创建、暂停、归档、合并来源；节点记录追加与刷新恢复。
- 位置授权成功、拒绝、超时/不可用；未经点击不调用Geolocation。
- 地图无Key不编造地点；供应商失败回退通用环境建议。
- 提示词注入、政治敏感、违法、暴力、色情等继续拒绝。
- 前端lint、typecheck、build与核心E2E。

### 第二层：真实冒烟

- “四川菜”+“夜间消费场景”调用商业透视，记录模型、耗时、首测结构合规和修复情况。
- “四川菜”请求方向建议，人工判断候选是否互补而非同义改写。
- 使用真实图谱摘要请求环境建议，确认不保证灵感、不编造事实。
- 地图Key未提供时明确记录真实POI冒烟待验，不能用fallback冒充。

## 十一、产品经理验收清单

- [ ] 首页输入主题后可以选择商业深思或日常发散。
- [ ] 可以自己填写方向，也可以让AI提供2–3个方向并编辑后采用。
- [ ] 商业深思画布能看出横向业态与纵向产业链不是同一类节点。
- [ ] AI内容先虚化，点击接受后才成为正式内容。
- [ ] 选择一个节点，可以创建独立思考分支。
- [ ] 可以在节点上追加一条记录并标为关键发现/待验证，刷新后仍存在。
- [ ] 点击“换个环境想一想”后才出现位置说明与授权请求。
- [ ] 拒绝定位后仍能继续思考，并看到不依赖实时地点的环境建议。
- [ ] 回到项目列表后，存档、复制和删除仍可使用。
- [ ] 手机端可以完成上述核心流程，没有侧栏遮死画布。

## 十二、风险与待确认项

- 高德Key、配额、调用费用和隐私条款尚未提供；因此真实附近POI只完成适配能力，不作为无Key环境下的已验收项。
- IndexedDB只适合当前单浏览器体验。进入正式账户、付费与跨设备阶段前必须迁移服务端数据库。
- 商业洞察可能具有事实幻觉风险，界面必须标注“思考线索/待验证”，后端禁止把无数据支撑的内容表达为确定事实。
- 现有Node 24高于手册默认Node 22，但当前项目已构建通过；不在本阶段降级，部署运行时仍使用已验证的Node 20镜像。
